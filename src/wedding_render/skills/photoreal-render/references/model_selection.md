# P0 · 多模态编辑模型选型实验包

目标：用最小成本（每模型 6~8 次生成）确定照片级化用的模型。
候选：dashscope(qwen-image-edit) / openai(gpt-image-1) / gemini(image, nano banana) / 其他（SiliconFlow flux-kontext 等）。

## 统一评估表（每模型一份）

| 维度 | 说明 | 1-5分 |
|---|---|---|
| 布局一致性 | 输入图物体位置/数量/透视是否保持 | |
| 材质真实感 | 织物/花材/金属是否像实拍 | |
| 花艺细节 | 花的自然度、层次、不重复感 | |
| 光照氛围 | 黄昏/夜灯是否可信 | |
| 指令遵循 | 锁定布局、指定色系是否被遵守 | |

## 实验一：风格迁移组（验证"元素组合"核心动作）

输入：案例图 A（取布局）+ 案例图 B（取花艺风格）
prompt：
```
参考第二张图的花艺风格与色系，重新设计第一张图中的婚礼布置。
保持第一张图的空间布局、机位与构图不变，将拱门花艺与桌花替换为第二张图
同款风格：同样的花材、色彩、形态。照片级婚礼实拍质感。
```
通过线：A 的布局基本未变，且花艺明显呈现 B 的特征。

## 实验二：骨架照片级组（验证主管线，最关键）

输入：一张色块示意图（P2 前可用手工示意图/草图代替；P2 后用真实骨架渲染图）
prompt：使用 `photoreal.py --dry-run` 生成的正式 prompt（dusk 时段、ceremony_front 机位）。
通过线：色块被正确翻译为对应材质（白→纱幔花艺、暖黄→串灯），布局锁定不漂移。

## 实验三：布局保持组（验证局部修改能力）

输入：实验二的最佳成品图
prompt：
```
保持整张图完全不变，只把拱门花艺从白绿色系换成香槟金色系（玫瑰+干花），
其余物体位置、光照、构图严格不动。
```
通过线：只有拱门花色变化，其他区域像素级近似。

## 执行方式

1. `export <PROVIDER>_API_KEY=...`
2. 逐实验调用 `photoreal.py`（--dry-run 先确认 prompt）
3. 每次生成立即把输入/输出/评分记入本文件末尾的记录表
4. 全部完成后：按总分选型，更新 README 与 photoreal.py 的默认 provider

## 选型结论（2026-08-25）

**选定 qwen-image-3.0（标准版，DashScope 同步 multimodal-generation 端点）**：
- 布局锁定能力达标（三组实验 4~5 分），无需 ControlNet 兜底，无需本地 ComfyUI
- prompt_extend_mode 必须为 direct（agent 模式 I2I 会 400）
- 生成图 URL 24h 有效，脚本已即时下载落盘
- 待验证：qwen-image-3.0-pro 与标准版的画质差是否值得差价（出正式方案图前用 pro 跑一次对比）
